# AP RuleLayout v1.0: Rules in four rows

## TL;DR

The settings page's MIME types and extensions leave their tables:
each rule becomes a block of four rows on a two-column grid
that folds to one column where the list is narrow,
as the sketch the user approved shows.

- `<table>` of rules → `<ul class="lfp-rules">`, one `<li>` per rule (`RuleRow`)
- row 1: name, switch, Reset/Remove (a button) | providers, on one baseline
- row 2: minimum | maximum, each with its label above it and its Save
- row 3: the note - no effect, or the renderer missing - where there is one
- row 4: the `occ` command, full width
- providers start where the maximum starts; all of them move to a full-width row
  together once the longest chain no longer fits that column (a `ResizeObserver`)
- below 40rem of list width: one column (a container query)

### Blocks

1. The four-row rule, its folding, the providers' row; tests, CHANGELOG.
2. Screenshots of the MIME types and extensions retaken.

## Analysis

- `RuleRow.vue` renders a `<tr>` of five cells;
  `TypesSection.vue` wraps the rows in two `<table>`s with column headers.
  The headers named the size fields, so `NumberField`'s `labelOutside`
  hid its label and set `aria-label` instead.
  Without headers, the label is shown again, outside and above the field,
  as a `<label for>`, where it does not cover the placeholder.
- `NcTextField` puts its `id` on the `<input>`, so `<label for>` names it.
- An extension has no providers.
  Its first row is then its name alone, across both columns,
  so that its sizes do not move up beside it.
- CSS cannot compare one rule's content with the other rules',
  so whether the providers get a row of their own is measured:
  the widest chain's `max-content` width against the second column's width,
  on every resize of the list and every change of the types.
  The decision is a pure function, unit tested;
  the measuring needs a browser and is checked by eye and by Cypress.
- `NcCheckboxRadioSwitch` sets its own baseline,
  which may need a correction for row 1 to line up.
- The `tr[data-mime]`, `tr[data-extension]` selectors in
  `tests/e2e/settings.cy.js` and `screenshots.cy.js`, and the Vitest specs
  that check `labelOutside`, follow the new structure.
- The column-header texts nobody shows any more leave the translations
  through `scripts/l10n.sh update`; the two new labels are translated.

## Implementation Plan

### Block 1: The four-row rule

1. `NumberField.vue`: `labelOutside` shows the label above the field,
   a `<label for>`; `narrow` goes, the rule's CSS sizing its fields.
2. `RuleRow.vue`: an `<li>` with head (name, switch, reset/remove as a
   secondary button), providers, minimum, maximum, note, command,
   in that order; labels `Minimum, MiB` and `Maximum, MiB`.
3. `TypesSection.vue`: each list a `<ul class="lfp-rules">`;
   the providers' row from a new `useProvidersRow.ts`.
4. `settings-admin.css`: the grid, the container query, the full-width
   providers, the baseline of row 1; the table rules that only rules used go.
5. Specs: `NumberField.spec.ts`, `TypesSection.spec.ts`,
   `useProvidersRow.spec.ts`; the Cypress selectors.
6. Translations: `scripts/l10n.sh update`, the new texts in `de` and `de_DE`,
   `build`.
7. `CHANGELOG.md`: the settings bullet amended.

**Verification:** `npm run lint`, `typecheck`, `stylelint`, `npm test`,
`npm run build`, `scripts/l10n.sh check`;
`tests/e2e/settings.cy.js` against the harness instance,
and a look at the page at a wide and a narrow width.

### Block 2: Screenshots

1. `tests/e2e/screenshots.cy.js`: its selectors follow the new structure.
2. `docs/Screenshots/MIME-Types.png`, `Extensions.png` retaken
   (the others where they changed).
