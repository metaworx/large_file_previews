# AP Cypress v1.0: browser tests and screenshots

## TL;DR

Browser tests for the settings page and the install,
ported from another app of ours, plus specs of this app's own,
a screenshot run for the App Store listing, and both run in CI.

- Cypress: none → pinned to exactly 15.20.0, already in the local cache
- Enable test: ported → the Apps page enables the app, and the settings show
- Settings page: unit tests only → `7z` refused;
  a valid extension added and listed in *What is processed*;
  a stored value shown as stored, and the same through `occ`;
  the help popover clear of *Save*
- German: the page in `de` and `de_DE` shows translated texts
- CI: a Cypress job on Nextcloud 33 to 35;
  the install check gains an Apps-page mode
- Screenshots: none → `CYPRESS_capture=1` writes `docs/Screenshots/`,
  which `info.xml` names
- No other app's name in code or comments

### Blocks

1. Scaffold: the pinned dependency, the config, the support file,
   the ignore files, `tests/e2e/README.md`.
2. Specs: enable, the settings page, German.
3. CI: the serve and Cypress actions, the server's E2E settings,
   the frontend into the server, the Cypress job, `l10n.sh check` in lint,
   CI.md.
4. Install check: an Apps-page mode against the fake store,
   and a smoke spec after it.
5. Screenshots: the capture spec, `docs/Screenshots/`,
   `<screenshot>` in `info.xml`, the README.

## Discussion

Settled with the user on 2026-10-15:

- **Ported, not invented:**
  the other app's Cypress setup,
  its enable test and its screenshot script are the starting point.
  Its app-specific commands, fixtures and specs are left behind.
- **The settings spec tests an extension that is refused (`7z`) and one that is
  accepted, and reads the *What is processed* table.**
- **Cypress is not downloaded again:**
  version 15.20.0, the one in `~/.cache/Cypress`,
  pinned exactly so that npm never resolves a newer one.
  The npm package itself comes from npm's cache where it is there
  (`--prefer-offline`); otherwise it is a download of a few MB,
  named at the gate before it runs.

Open, for the plan gate:

- **The run:**
  blocks 1 to 5 under `PLAN++`, each committed and pushed to GitLab,
  or block by block.
- **Screenshots in dark as well as light.**
  The other app captures light only; this plan does the same,
  and dark is a second pass of the same spec where wanted.

## Analysis

- **The other app's setup** (surveyed 2026-10-15):
  - `cypress.config.cjs`, CommonJS because `package.json` is `"type": "module"`,
    as it is here: `baseUrl` from `CYPRESS_baseUrl`, else `DDEV_PRIMARY_URL`,
    else the harness URL; specs `tests/e2e/**/*.cy.js`;
    support `tests/e2e/support/e2e.js`;
    `after:screenshot` moves the capture spec's images to
    `docs/Screenshots/<name>.png`; Chrome started with `--no-sandbox`,
    `--disable-dev-shm-usage`, `--lang=en-US`.
  - The support file: `cy.login` in a `cy.session`,
    an `uncaught:exception` filter that fails only on the app's own errors,
    a sweep of the auth tokens Cypress creates,
    and a diagnostic after a failure.
    Most of the rest is that app's own.
  - `occ` comes from `CYPRESS_occ`: `php nextcloud/occ` in CI,
    `nextcloud_testing/scripts/nc-test <instance> occ` against the harness.
  - The enable spec disables the app by `occ`, enables it on the Apps page,
    confirms the password, and opens the settings.
  - The store spec installs a release from the Apps page,
    skipped unless `CYPRESS_storeInstall` names a version.
  - The capture spec runs only with `CYPRESS_capture=1`,
    forces the light theme and restores it, at 1600 x 900.
  - CI: a job per Nextcloud version with MariaDB,
    the server served by `php -S` (`nextcloud-serve`),
    `cypress-io/github-action` with Chrome (`cypress-run`),
    screenshots uploaded on failure.
    `nextcloud-server` has an E2E step: no web updater, app store on,
    English forced, no first-run wizard, cron.
    `app-into-server` can build the frontend into the server.
  - `install-check.yml` has a `mode` matrix, `occ` and `web`,
    the web mode installing through the Apps page with the store spec,
    then a smoke spec.
- **Here:**
  - The settings mount `#lfp-admin-settings`, under *Additional settings*:
    `/index.php/settings/admin/additional`.
  - The harness instance is `nextcloud-34-lfp`,
    at `https://nextcloud-34-lfp.ddev.site`, with `nc-test 34-lfp occ`.
  - An extension is added with the field *Extension, e.g. tif* and *Add*,
    saved as `{ enabled: true }`;
    the server refuses one whose MIME type the app does not handle with
    "Files .7z are application/x-7z-compressed, a type this app does not handle."
  - An extension whose MIME type is disabled, such as `heic` by default,
    adds a row to *What is processed*;
    one whose MIME type is already enabled shows
    "No effect: its MIME type already selects it".
  - The two defects reported on 2026-10-15 -
    a MIME field showing the shipped default rather than the stored value,
    and the ⓘ over *Save* - were invisible to Vitest;
    the settings spec checks both.
  - `tests/` and every file at the root are outside `project.shipped`,
    so blocks 1 to 4 owe no CHANGELOG bullet; block 5 changes `info.xml`,
    which does.

## Implementation Plan

1. **Scaffold.**
   - `package.json`:
     `cypress` `15.20.0` exactly, in `devDependencies`;
     the lock updated with `npm install --prefer-offline`.
   - `cypress.config.cjs`:
     the other app's, its base URL the harness's
     `https://nextcloud-34-lfp.ddev.site`,
     its diagnostic task named generically.
   - `tests/e2e/support/e2e.js`:
     login, the token sweep,
     the exception filter (the app id read from `Cypress.env` or set once),
     the failure diagnostic, and `cy.occ()` over `CYPRESS_occ`.
   - The ignore files:
     `/cypress/` in `.gitignore`;
     `/cypress.config.cjs` and `/cypress` in `.nc.publish.ignore`;
     `cypress.config.cjs` in `.l10nignore`.
   - `tests/e2e/README.md`:
     what each spec checks, and the commands against the harness and in CI.

   **Verification:**
   `npx cypress verify` finds 15.20.0 without a download;
   `git status` shows no `cypress/` output.
2. **Specs.**
   - `tests/e2e/app-enable.cy.js`:
     ported; the app enabled on the Apps page,
     then disabled there and enabled again by `occ`,
     and the settings page showing "Large File Previews, v<version>".
   - `tests/e2e/settings.cy.js`, each test restoring what it set by `occ`:
     - `7z` added → the refusal shown, no row,
       nothing stored (`lfp:config:show`);
     - `heic` added → a row under *Extensions*,
       and a `.heic` row in *What is processed*; removed → both gone;
     - `pdf` added → "No effect: its MIME type already selects it";
     - a MIME type's minimum set and saved → after a reload the field shows it,
       and `lfp:config:get` reports it; reset → the field empty,
       the default its placeholder;
     - every ⓘ's popover, opened,
       clear of its row's *Save* (bounding boxes do not meet).
   - `tests/e2e/l10n-german.cy.js`:
     the admin's language set to `de`, then `de_DE`, by `occ user:setting`,
     and the page showing „Was verarbeitet wird“ and „Speichern“;
     restored after.

   **Verification:**
   the three specs pass against `34-lfp`,
   with `CYPRESS_occ="nc-test 34-lfp occ"`.
3. **CI.**
   - `.github/actions/nextcloud-serve` and `.github/actions/cypress-run`:
     ported.
   - `.github/actions/nextcloud-server`:
     an `e2e` input, off by default, whose step sets what the other app's does;
     the PHPUnit job leaves it off and is unchanged.
   - `.github/actions/app-into-server`:
     a `frontend` input that builds `js/` and `css/` into the server.
   - `test.yml`:
     a job `e2e`, Nextcloud 33 to 35 with MariaDB, the specs of block 2,
     screenshots uploaded on failure; the MariaDB service shared by an anchor;
     `scripts/l10n.sh check` in the lint job's guideline checks.
   - `GUIDELINES/project/CI.md`:
     §1, §2, §4 and §7.

   **Verification:**
   the mirror's run of the commit is green, the `e2e` job included.
4. **Install check.**
   - `install-check.yml`:
     a matrix `mode: [occ, web]`; `web` lists the fake store in the server,
     serves it,
     installs through the Apps page
     (`tests/e2e/store/install-from-apps-page.cy.js`, ported),
     then runs `check-install.sh` and the settings spec as a smoke test.
   - `GUIDELINES/project/CI.md` §6.

   **Verification:**
   `actionlint` where it is installed, else a careful read;
   the workflow runs only for a release, so its first run is the first tag's,
   which the completion gate says.
5. **Screenshots.**
   - `tests/e2e/screenshots.cy.js`:
     only with `CYPRESS_capture=1`; the light theme forced and restored,
     1600 x 900; the whole page,
     the types with a few rules and the processed table, the limits,
     the status with a missing program.
   - `docs/Screenshots/*.png`, made against `34-lfp`.
   - `appinfo/info.xml`:
     a `<screenshot>` per image, GitLab raw URLs at the release tag,
     in a `RELEASE-PIN` block so that `changelog.sh cut` moves them with the
     version.
   - `README.md`:
     the screenshots, and the command that makes them.
   - `CHANGELOG.md`:
     a bullet.

   **Verification:**
   the images open and show what their names say;
   `info.xml` validates against the store's schema; `changelog.sh check` passes.
