# NOTE Sandbox v1.0: deviations

Where the run of Blocks 1 to 4 went differently from the plan.

- **Nextcloud's config and data directory are hidden inside the sandbox**,
  which the plan did not have.
  D2-A binds all of `/etc`, on the premise that the web user reads no secret there;
  a distribution's package may keep `config.php` under `/etc`
  (Arch `/etc/webapps/nextcloud`, Alpine `/etc/nextcloud`),
  where the web user must read it.
  `Sandbox::masks()` lays an empty folder over each folder holding a config file
  Nextcloud read in the request (`get_included_files()`), and over the data directory,
  wherever a bind shows them. Nextcloud has no public word for its config's folder,
  and `\OC::$configDir` would break the contract's public-API rule.
- **No CI result.** The run stops before a push, so the integration tests,
  which skip in the harness (no bwrap, user namespaces refused),
  have not run anywhere with a Nextcloud. On the host, the arguments `Sandbox` builds
  rendered a text PDF identical to an unsandboxed render;
  the integration test's own probe printed `lo` and `end` only;
  a mask emptied `/etc/apt`; the chain kept its exit statuses
  (124 timeout, 137 killed, 153 file-size cap).
- **The fontconfig cache made no measurable difference** for the PDF tried,
  whose fonts are embedded: 147 to 168 ms sandboxed with or without it,
  142 to 200 ms unsandboxed. It stays bound, for PDFs that use the system's fonts.
- **A translation in the wrong register, fixed in Block 3:**
  `de`'s WebP hint, from AP PreviewStream, said *wählen Sie*;
  the glossary has `de` in *du*: *wähle*.
